자료 기준: 2026년 10월 29일

이 교재는 사용자의 원문을 학습 교재로 편집한 결과입니다. 이번 웹페이지 제작에서 Hermes 공식 문서의 최신 상태나 소스 구현을 추가로 검증하지 않았습니다. 원문의 검토 범위와 한계를 아래에 보존했습니다.

0. 읽기 안내와 검증 범위#

0.1 이 문서의 학습 방법#

  • 기초 (1~4장): 'Hermes가 무엇인가?', 'LLM과 Agent는 어떻게 다른가?', '어떤 구성요소가 있는가?'부터 이해한다.
  • 구조 (5~13장): 하나의 요청이 실행되고 저장되는 과정, Prompt, Tool, Memory, Skills, MCP, Subagent의 역할을 연결한다.
  • 코드 (14~17장): 실제 소스 파일의 책임과 함수 경계, 흐름, 예외·보안 처리를 추적한다.
  • 설계 (18~22장): 반도체 데모 적용성, 기술적 장단점, 향후 6개 기술 비교에 필요한 의사결정 기준을 정리한다.

표기 규칙:

표기 뜻
[공식] 공식 문서에서 명시적으로 설명한 사실
[코드] 공식 GitHub 공개 코드 또는 공식 개발 가이드가 특정 구현에 연결한 사실
[해석] 위 근거를 이용해 정리한 기술적 판단
[예시] 학습 목적으로 작성한 가상 시나리오·의사코드. 실행·검증 완료 코드가 아님
[확인 필요] 선택한 설치 버전, 배포 환경, 실제 실험으로 검증해야 할 조건

중요한 한계: 이번 조사는 공식 사이트와 공개 GitHub의 조회 가능한 내용에 대한 문헌·소스 검토이다. 저장소를 로컬에 클론해 테스트를 실행하거나 특정 커밋 전체를 감사하지 않았다. GitHub 링크는 조회 시점의 main 경로이므로 향후 파일 내용·함수명·기본값이 달라질 수 있다. 구현 직전에는 tag/commit SHA를 고정해 재검증해야 한다. 본문에 나오는 '간소화 코드'는 실제 원본 인용이 아니라 흐름을 설명하기 위한 재구성이다.

0.2 30초 핵심 요약#

Hermes Agent는 Nous Research가 공개한, 실행 기능을 이미 갖춘 범용 자율 Agent/Harness다. 모델 가중치 자체도, LLM 추론 서버도 아니다. 선택한 LLM의 응답을 바탕으로 도구를 실행하고, 결과를 다시 모델에 전달하고, 세션·기억·Skills를 관리하며, CLI·메신저·API 등으로 사용자와 연결한다. S01, S02

다음 네 문장을 먼저 기억하자.

  1. LLM이 '다음에 무엇을 할지' 결정하고, Hermes Runtime이 실제 도구 호출·세션·권한·반복을 처리한다.
  2. Memory(기억)와 History(대화 이력)와 Skills(작업 절차)는 서로 다른 저장·검색 경로를 가진다.
  3. Hermes의 자율성은 LLM의 행동 선택 + Hermes의 실행 루프/권한/환경이 결합된 결과이지, 모델이 운영체제 명령을 직접 실행하는 것이 아니다.
  4. '자기 개선(self-improving)'은 주로 기억·Skills의 자동 기록·수정·정리를 가리킨다. 이것을 Hermes 모델 가중치의 자동 재학습과 혼동하면 안 된다.

B.3 재검증 절차 (개발 착수 직전)#

  1. 공식 GitHub에서 학습할 release/tag 및 정확한 commit SHA를 고정한다.
  2. git grep/IDE 검색으로 함수·파일 존재와 실제 호출관계를 확인한다.
  3. 해당 commit의 공식 문서·예제·테스트와 코드가 일치하는지 확인한다.
  4. 회사 보안정책을 만족하는 최소 설정의 로컬/격리 PoC를 만든다.
  5. 고정된 Model + 합성 데이터 + Tool + 평가 질문으로 반복 실험한다.
  6. 측정 결과를 기반으로 본 문서의 정성적 판단을 실증적 판단으로 업데이트한다.

최종 결론: Hermes는 완성형 Agent Harness가 실제로 어떻게 구성되는가를 배우기에 풍부한 공개 사례다. 다만 반도체 Agent 선택 기준은 기능 개수보다 정확성·재현성·데이터 접근 통제·도구 실행의 안전성·운영 가능성에 둬야 한다. 본 문서는 그 선택을 위한 기초 지식과 소스코드 탐색 지도로 사용한다.
