19.2 발표 본문에 넣을 코드의 양#

발표 본문은 핵심 코드 3개 정도만 권장한다. 나머지는 기술 학습 부록에 남긴다.

  1. Loop의 종료 조건: max_iterations와 Budget, 분기·최종화.
  2. Tool 실행의 Persist-before-execute: 저장 실패 시 Tool 실행을 막는 코드.
  3. 병렬 Executor: _plan_tool_batch_segments와 Daemon Pool 실행.

Cache, Memory, Cron은 도식과 짧은 데이터 흐름으로 설명하고, 실제 함수는 발표 노트 또는 Appendix에 연결한다.

19.3 슬라이드마다 전달할 문장#

  • Loop: "에이전트의 자율성은 모델이 아니라, 모델 행동을 반복하고 제어하는 Runtime에서 완성된다."
  • Cache: "입력을 다시 보내더라도 서버의 Prefix 계산은 재사용될 수 있다."
  • Memory: "메모리 파일을 쓴다는 것과 현재 Prompt가 갱신되는 것은 별개다."
  • Retrieval: "FTS는 저장소의 검색 방식이고, RAG는 검색 정보를 생성에 활용하는 아키텍처다."
  • Skill: "Skill 작성과 Skill의 신뢰성 검증은 별도 과정이다."
  • Security: "Prompt의 금지 지시보다 실제 Tool 실행 경계가 중요하다."
  • Concurrency: "병렬 실행은 빠름의 문제가 아니라 충돌·중단·결과 정합성의 문제다."
  • Serving: "Agent API는 한 번의 모델 API 호출을 감싼 것이 아니라 실행 중인 작업의 상태를 관리하는 서비스다."

20. 학습을 마친 뒤 직접 답할 수 있어야 할 심층 질문#

다음 질문을 문서나 코드를 열지 않고 간단한 시퀀스나 의사코드로 설명할 수 있다면 원하는 학습 수준에 가까워진 것이다.

20.1 개념과 이유#

  1. SDK, Library, Framework, Harness, Agent Runtime, Model Serving은 어떤 관계인가?
  2. Prefix를 매번 보내는데 Cache Hit가 가능한 이유는? 서버와 Client의 역할을 구분하여 설명.
  3. System Prompt 앞부분의 Timestamp가 자주 바뀌면 왜 Cache 효율이 떨어지는가?
  4. Context Compression과 session_search는 왜 대체관계가 아닌가?
  5. Hermes의 Memory, SQLite Session, Skill의 소유권과 갱신 시점을 설명.
  6. FTS5의 역색인·Trigram·CJK Bigram이 해결하는 검색 문제는 서로 무엇이 다른가?
  7. FTS 기반 Session Retrieval도 RAG인가? RAG와 Vector Retrieval을 구분.
  8. Skill이 스스로 생성된다는 말의 실제 Tool 실행 의미는 무엇인가?
  9. MCP는 왜 Agent Framework/Loop가 아니라 연결 프로토콜인가?
  10. Plugin은 MCP와 달리 어떤 런타임 내부 동작을 확장할 수 있는가?

20.2 코드 및 실행 흐름#

  1. run_conversation()이 첫 모델 호출 전 준비하는 상태를 순서대로 설명.
  2. 모델이 Tool 3개를 요청했을 때 어떤 순서로 이름·인자·유효성을 검사하는가?
  3. run_tool_round()이 Tool 실행 전에 DB에 먼저 쓰는 이유와 실패 처리.
  4. 언제 Tool들을 병렬로 묶고 언제 순차 배리어가 필요한가?
  5. DaemonThreadPoolExecutor의 Worker Timeout은 외부 효과까지 취소하는가?
  6. Tool 결과 순서를 모델이 호출한 순서에 맞춰 정리하는 이유는?
  7. MEMORY.md 수정 이후 현재 Session Prompt를 유지하는 이유는?
  8. Context Compressor가 Skill Body를 삭제했을 때 재로딩을 어떻게 유도하는가?
  9. check_all_command_guards()의 강제 차단과 사용자가 승인할 수 있는 위험은 어떻게 다를까?
  10. Child Agent와 Parent의 Context, Toolset, Task ID, 비용은 어떻게 분리되는가?
  11. Gateway의 Session Authority가 없고 Client가 각자 SQLite를 쓴다면 어떤 Race가 생길까?
  12. Cron의 예약 시각 1회를 Claim하는 것과 실제 API 작업을 Exactly-once 실행하는 것의 차이는?

20.3 설계 Trade-off#

  1. 왜 개인용 Agent에 SQLite+FTS5가 합리적인 선택일 수 있나?
  2. 언제 Hybrid Retrieval을 추가해야 하며 그때 늘어나는 운영 부담은 무엇인가?
  3. 어떤 Skill을 Auto-write 허용하고 어떤 Skill을 승인해야 하는가?
  4. Tool 권한을 LLM System Prompt로만 강제하면 왜 취약한가?
  5. 여러 Child Agent를 동시에 실행하면 처리 시간이 반드시 줄어드는가?
  6. API가 즉시 최종 결과를 반환하는 방식과 Run ID 기반 비동기 방식의 차이는?
  7. Cron, Webhook, Queue, Durable Workflow는 각각 어떤 Trigger/수명주기를 담당하는가?
  8. 다음 프레임워크를 연구할 때 Hermes와 어떤 실행 경로를 동일한 기준으로 비교할 것인가?
