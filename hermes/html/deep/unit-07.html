8. Built-in Memory: 파일을 누가 언제 어떻게 쓰는가?#

8.1 MEMORY.md는 Agent가 판단해서 직접 수정할까?#

그럴 수 있다. [DOC][SRC] Hermes의 기본 Memory 시스템은 두 파일을 사용한다.

파일 목적 기본 크기 제한 기본 동작
memories/MEMORY.md 환경 사실, 작업 규칙, Agent 메모 약 2,200자 Agent가 memory Tool을 통해 추가·교체·삭제 가능
memories/USER.md 사용자 선호·프로필 약 1,375자 Agent가 별도 대상에 기록

경로는 무조건 전역 ~/.hermes로 고정된 것이 아니라 현재 프로필의 HERMES_HOME/memories/를 기준으로 해석한다. 사용자가 파일을 직접 편집하는 것도 가능하나, Hermes가 제공하는 Memory Tool과 승인 경로를 통한 수정을 따르는 편이 일관성·검증·감사 측면에서 좋다.

8.2 핵심: 세션 중 기록해도 System Prompt는 즉시 바뀌지 않는다#

[SRC] tools/memory_tool.py 상단에 Memory의 Frozen Snapshot 정책이 명시돼 있다. 세션 시작 시 파일 내용을 System에 반영하고, 세션 중 Tool이 파일을 써도 이미 고정한 System Prefix는 바꾸지 않는 방식이다. 이것은 세션 연속성과 Prefix Cache를 위해 의도된 선택이다.

원본: https://github.com/NousResearch/hermes-agent/blob/v0.22.5/tools/memory_tool.py#L1-L4
문서: https://hermes-agent.nousresearch.com/docs/user-guide/features/memory

질문: 저장한 즉시 모델이 그 사실을 알 수 없는가?
현재 모델이 Tool 실행 결과에 기록 성공 내용을 보게 될 수는 있다. 하지만 System Prompt에 들어간 고정 Memory Snapshot이 최신 파일로 교체되는 것과는 다른 문제다. 이미 실행 중인 다른 Session에도 새 Memory가 자동으로 나타나는 것은 아니다.

8.3 실제 Memory Tool 경로#

원문 흐름·데이터 예시text
모델이 memory Tool Call 결정
  -> Agent Inline Tool 처리
  -> memory_tool(action, target, content, ...)
  -> 쓰기 승인/사전 검증 단계
  -> MemoryStore에 원자적인 변경 적용
  -> JSON 결과를 Tool Role로 반환
  -> 디스크 파일과 다음 Session Snapshot에 반영

[SRC] tools/memory_tool.py::memory_tool()은 단일 동작 또는 operations Batch를 처리하며, MemoryStore를 필요로 한다. 이 파일은 승인/보류 경로를 처리하고, 실제 Store의 크기 제한·콘텐츠 검사 등은 tools/memory_tool_store.py로 위임한다. 저장 성공 여부는 Tool 반환값과 실제 파일 모두 확인할 수 있다.

8.4 '알아서 기억하기'는 LLM의 판단과 비결정적 도구 실행에 의존#

  • System Instruction은 모델에게 어떤 사실을 저장할지 유도할 수 있다.
  • 모델이 실제 memory Tool Call을 하지 않으면 파일은 바뀌지 않는다.
  • 공식 문서는 모델이 저장했다는 텍스트만 말하고 Tool을 호출하지 않을 수 있음을 명확히 경고한다.
  • Turn 이후 Background Review가 새로운 Memory 저장/수정 후보를 만들 수도 있다.
  • 잘못 추론한 사실이 Memory가 되면 다음 Session들에 오염을 전파할 수 있다.

설계 해석: '모델이 판단해서 적는다'는 구현하기 쉽지만, 기억할 가치·사실성·적용 기한을 검증하는 제어 계층 없이는 데이터 품질을 보증할 수 없다. [INF]

8.5 승인 정책을 반드시 분리하여 공부#

[DOC] memory.write_approval: true를 사용하면 Memory 쓰기를 사용자 승인 대상으로 만들 수 있다. CLI에서는 즉시 승인할 수 있고, 비대화형/백그라운드 실행에서는 Pending 큐에 들어가 승인이 오기 전에는 반영되지 않는다. 기존 텍스트를 교체/삭제하는 작업에는 타깃의 변화를 확인해 오래된 승인 내용이 무심코 적용되는 일을 방지하는 제약도 있다.

원문 수록 코드 예시 · 실행 미검증yaml
# 문서상 설정 예시 — 실행 테스트 수행하지 않음
memory:
  write_approval: true

8.6 Memory vs Session vs Skill#

질문 Memory Session Skill
무엇을 담나? 짧은 지속 사실·선호 특정 대화 전체 재사용 가능한 절차와 지침
어떻게 로드하나? 새 Session 시작 시 System Snapshot Resume/History 조회 인덱스 상시, 본문 필요 시 로드

내용 변동 리스크 전역 규칙 오염 과거 대화 오염 반복 실행 절차의 오류 확산

8.7 '메모리'에 과도한 의미를 부여하지 말 것#

Hermes의 Built-in Memory는 지식그래프·벡터 데이터베이스·모델 가중치 수정이 아니다. 에이전트의 자기 개선이라는 표현은 지속 데이터와 절차를 다음 실행에서 재사용하는 능력을 의미할 수 있으며, 이것이 곧 LLM 자체가 Fine-tuning 되는 것이라는 뜻은 아니다.
