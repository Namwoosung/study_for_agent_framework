시작점: Hermes는 무엇을 하는가?

LLM은 텍스트와 도구 호출 요청을 생성합니다. 파일을 읽고, 함수를 실행하고, 결과를 다시 모델에 전달하려면 실행을 관리하는 시스템이 필요합니다. Hermes Agent는 이러한 반복 실행·도구·세션·기억·작업 절차를 갖춘 범용 Agent Harness입니다. [S01] [S02]

이 교재에서는 “기능이 있는가”에서 한 걸음 더 들어가, 누가 판단하고, 누가 실행하며, 무엇을 저장하는가를 연결해 읽습니다.

읽는 동안 유지할 세 가지 구분

모델의 판단 / Runtime의 실행
Tool Call은 실행 요청 데이터입니다. 실제 함수 호출과 실행 권한은 Runtime 및 실행환경이 처리합니다.
현재 입력 / 기억 / 과거 이력 / 작업 절차
Context는 현재 요청의 정보, Memory는 재사용할 사실, History는 대화 기록, Skills는 작업 방법입니다. 서로 다른 저장·검색 경로를 가집니다.
지식 갱신 / 모델 가중치 학습
기억과 Skill을 기록·수정하는 자기 개선을, 기반 모델의 자동 재학습으로 해석하면 안 됩니다.

원문 0·2·9·10장에 근거한 편집 요약입니다. 원문의 표기와 검증 범위를 함께 확인하세요.

  2. 02요청이 실행되는 전체 경로입력 → 모델의 판단 → 도구 실행 → 관찰 → 응답→
  3. 03모델이 보는 정보 구성하기정체성, 프로젝트 지침, 현재 대화를 어떻게 연결하고 유지할까?→
  4. 04기억과 대화 이력 나누기짧은 사실의 주입과 과거 대화의 검색은 다른 경로다→
  5. 05작업 방법을 절차로 남기기SKILL.md가 재사용되는 과정과 자기 개선의 정확한 범위→
  6. 06도구 요청을 실제 함수로 연결하기모델이 보는 계약과 실제 Handler의 책임→
  7. 07위임과 메시지 운영 이해하기별도의 Context를 가진 자식 Agent와 세션을 연결하는 입력 계층→
  8. 08실제 소스의 경계를 따라 읽기진입점 → Prompt → Loop → Tool → 저장·복구→
  9. 09권한과 운영 조건 설계하기모델의 지침 준수와 시스템이 강제하는 통제를 분리한다→
