작업 방법을 절차로 남기기

SKILL.md가 재사용되는 과정과 자기 개선의 정확한 범위

원문 10장

먼저 연결해 보기

Memory가 “무엇을 알아야 하는가”에 대한 짧은 사실이라면, Skill은 “이런 일을 어떤 순서로 할 것인가”에 대한 절차입니다. 절차를 담은 문서를 읽는 것과 실제 도구를 실행하는 것은 별개의 단계입니다.

Skill 전체를 매번 입력하기보다는 목록에서 관련 항목을 고르고, 필요할 때 본문과 참고 자료를 읽습니다. 실행 경험으로 Skill을 갱신해 재사용하는 흐름이 원문에서 설명하는 자기 개선의 중심입니다. 모델 가중치의 자동 재학습과 구별하고, 잘못된 절차도 다시 사용될 수 있다는 한계까지 함께 읽으세요.

읽는 관점목록 → 절차 본문 → 상세 참조의 로딩 순서와, 절차 변경의 검증·승인 경계를 확인하세요.

10. Skills: Agent의 '작업 방법'을 저장하는 체계#

10.1 Memory와 Skills의 차이#

  • Memory: '이 프로젝트의 데이터는 UTC 기반이다'처럼 사실을 남긴다.
  • Skill: '장비 이상 로그를 분석할 때 먼저 시간대를 정규화하고 중복 측정을 제거한 뒤 기준 시점과 비교한다'처럼 절차·검증 방법을 남긴다.

Hermes Skills는 기본적으로 SKILL.md 중심의 문서형 지식이다. Skill 자체가 실행함수·모델·별도 Agent인 것은 아니다. 필요한 스크립트·참고 파일을 포함할 수 있지만, 실제 외부 작업에는 권한 있는 Tool을 사용해야 한다. S06

10.2 파일 구조와 간단한 예시#

구조·흐름 설명text
~/.hermes/skills/
└── semiconductor/
    └── wafer-anomaly-review/
        ├── SKILL.md
        ├── references/
        │   └── metric-definitions.md
        ├── templates/
        │   └── report.md
        └── scripts/
            └── validate_schema.py
학습용 Skill 문서 예시markdown
---
name: wafer-anomaly-review
description: Wafer-level measurement anomaly review procedure
version: 1.0.0
---

# Wafer Anomaly Review

## When to Use
Wafer별 측정값의 이상 패턴이 의심될 때

## Procedure
1. 데이터 출처, 스키마, 시간대와 단위를 확인한다.
2. ID 중복, 결측, outlier 처리 기준을 명시한다.
3. 설정된 기준선과 비교한다.
4. 근거가 부족하면 원인을 단정하지 않는다.
5. 결과·코드·실행시각·제약을 보고서에 기록한다.

## Pitfalls
- 모델이 임의로 관리 기준치를 생성하지 않도록 한다.

이는 사용자가 직접 만들 수 있는 가상 Skill 예시다. name 및 description 등이 포함된 YAML frontmatter와 SKILL.md 내용 구조를 학습하도록 작성했다. S06

10.3 Progressive Disclosure (점진적 로딩)#

Skills 전체를 매번 모델에 다 넣으면 토큰이 낭비된다. Hermes는 주로 다음 단계를 사용한다.

구조·흐름 설명text
Level 0: skills_list()               이름·설명 등 인덱스
Level 1: skill_view(name)            해당 SKILL.md 본문
Level 2: skill_view(name, path)      특정 참조 문서

핵심은 목록 → 관련 절차만 선택 → 상세 참조다. RAG와 닮은 '필요 시 검색/선택'은 있지만, 기본 Skills의 동작을 임베딩 검색으로 일반화하면 안 된다. S06

10.4 Agent가 Skills를 자동 작성·수정할 수 있나?#

그렇다. 공식 문서는 skill_manage가 Skills의 생성·수정·삭제·지원 파일 작성 등을 지원한다고 설명한다. 모델은 유용한 새로운 절차, 오류를 해결하며 배운 방법, 사용자 피드백 등을 미래의 Skill로 남길 수 있다. S06

그러나 '자기 개선'의 의미를 정확히 제한해야 한다.

구조·흐름 설명text
실행 경험 → 유용한 절차 판단 → skill_manage로 SKILL.md 생성/수정
                                   ↓
                            다음 작업에 재사용

이는 지식·행동 지침의 갱신이다. 자동으로 기반 LLM 가중치를 fine-tuning/LoRA 업데이트한다는 뜻은 아니다. skill_manage 도구 호출이 없거나 승인 대기 상태면 실제 파일이 바뀌지 않을 수 있다.

10.5 Curator: Skills가 무한히 쌓이는 문제의 보완#

Hermes는 오래 쓰지 않은 Agent 생성 Skill의 사용 이력을 추적하고 active → stale → archived 상태로 정리하는 Curator를 제공한다. 공식 문서에 따르면 무조건 삭제하지 않고 아카이브하며, 기본적으로 Agent가 생성한 Skill을 관리한다. interval_hours와 유휴시간 조건이 만족될 때 검토가 동작하고, 필요 시 보조 모델이 통합·수정 제안을 할 수 있다. S15

Skills의 생성·변경도 위험하다. 반도체 업무에서는 Skill 자동 쓰기 승인, 버전 관리, 사람이 검증한 내용만 운영 반영하는 절차를 권장한다. 특히 '지난 분석에서 맞았던 임계값'을 다음 공정의 공식 기준으로 자동 승격해서는 안 된다.

절차가 행동의 안내라면, 실제 행동을 수행할 함수는 어떻게 등록하고 연결할까요?
