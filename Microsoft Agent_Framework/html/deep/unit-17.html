29. 학습 완료 점검 문제#

A. 핵심 개념 (답을 설명할 수 있는가?)#

  1. 왜 MAF를 단지 ‘Agent Runner 1개’라고 설명하면 부정확한가?
  2. BaseAgent, RawAgent, Agent의 책임 차이를 구분할 수 있는가?
  3. ChatClient에 Function Invocation 기능을 둔 설계의 장점과 복잡성은 무엇인가?
  4. Tool Loop 1회와 Agent Run 1회의 관계는 무엇인가?
  5. Graph Workflow가 모델 없이도 실행될 수 있는 이유는 무엇인가?
  6. Tool 등록을 단순 Python Callable 보관이라고 볼 수 없는 이유는?
  7. Pydantic 스키마를 통과한 인자를 그래도 인가해야 하는 이유는?
  8. Agent/Chat/Function Middleware는 각각 어디에서 실행되는가?
  9. MiddlewareFailure와 일반 Tool Exception의 핵심 차이는?
  10. MiddlewareTermination은 왜 별도 타입인가?

B. 상태·보안 (실제 실패 상황을 설명할 수 있는가?)#

  1. Session이 FileMemoryProvider와 같은 것이 아닌 이유는?
  2. File Memory Scope가 사용자 별로 분리되지 않을 때 생길 수 있는 문제는?
  3. Harness의 Tool Approval에서 Standing Approval이 오래 남으면 생길 위험은?
  4. 이미 승인된 인자를 하위 Middleware가 바꾸면 무엇을 검증해야 하는가?
  5. AgentLoopMiddleware가 should_continue=True만 반환해도 무한 반복하지 않도록 어느 조건을 확인해야 하는가?
  6. 정책 서비스가 다운됐을 때 Fail-open과 Fail-closed의 차이는?
  7. FIDES가 특정 CodeAct Provider 안쪽의 Tool 실행을 포괄하지 못한다는 사실이 의미하는 것은?
  8. Agent의 컨텍스트 압축과 모델 제공자의 Prefix Cache는 어떤 차이가 있는가?
  9. Function Tool 예외를 모델에 반환할 때 노출해서는 안 될 정보는 무엇인가?
  10. 부모 Agent의 승인 상태를 자식 Agent에 그대로 복사하면 어떤 위험이 있는가?

C. Workflow와 복구 (시퀀스로 설명할 수 있는가?)#

  1. Superstep 시작부터 완료까지 Event·State·Checkpoint의 순서는?
  2. 성공 시 commit(), 실패 시 discard()의 범위는 무엇인가?
  3. 서로 다른 Source가 같은 Executor에 동시에 보내는 메시지의 순서는 항상 같은가?
  4. Checkpoint의 iteration_count를 고유 ID로 사용하면 왜 위험한가?
  5. graph_signature_hash는 어떤 복구 실패를 줄여 주는가?
  6. Tool이 DB 저장에 성공하고 Workflow가 Checkpoint 전에 실패하면 어떻게 되는가?
  7. Tool Approval과 Workflow HITL의 승인 요청 상태는 어떻게 다른가?
  8. Functional Workflow의 asyncio.gather와 Graph Superstep의 동시성 모델은 어떻게 다른가?
  9. 모든 Workflow에 Agent가 필요한가?
  10. Agent.as_tool() 위임과 Workflow의 Handoff Orchestration은 어떤 차이가 있는가?

D. 프레임워크 설계 관점#

  1. 자신이 Tool 실행 엔진을 만든다면 어떤 함수 앞에 최종 인가 검사를 놓을 것인가?
  2. Agent/ChatClient/Tool/Workflow에 각각 어떤 인터페이스를 제공할 것인가?
  3. 외부 API 호출의 멱등성 키를 어느 계층에서 만들고 저장할 것인가?
  4. 서버에 100명이 동시에 접속할 때 Session 소유권을 어디서 관리할 것인가?
  5. Cron Job이 중첩되지 않도록 어떤 Lock/Queue 정책을 정의할 것인가?
  6. 새 모델 공급자를 연동할 때 최소 어떤 Tool Calling 계약을 검증할 것인가?
  7. 경로가 정해진 업무에 Multi-Agent 대신 Workflow를 쓰는 이유는 무엇인가?
  8. 어떤 메트릭으로 Loop·Tool·Workflow 수준의 실패를 구분할 것인가?
  9. 공개 코드를 확인한 주장과 실제 벤치마크가 필요한 주장을 어떻게 구별할 것인가?
  10. 7개 기술을 비교할 때 기능 개수보다 실행 계층과 권한 경계를 먼저 보는 이유는?
