Microsoft Agent Framework/승인과 Checkpoint

흐름과 복구 / 단원 06

멈추고 승인받고 상태 복원하기

승인 요청의 신원·재개 위치·외부 작업 중복

원문 15–16장

먼저 연결해 보기

승인은 특정 요청을 중단하고 정당한 응답을 받은 뒤 재개하는 과정입니다. 추가 정보 요청, Tool 승인, 보고서 검토 Gate를 같은 의미로 처리하면 안 됩니다.

Checkpoint는 Workflow 상태를 복원하지만 외부 시스템에 이미 발생한 효과까지 되돌리지는 않습니다. 승인 요청 ID와 세션 소유권, 외부 작업의 중복 방지와 저장 시점을 함께 읽으세요.

읽는 관점업로드 성공 직후 저장 전에 중단된다면, 재개 시 무엇을 확인해야 할까요?

15. Human-in-the-loop(HITL)와 승인#

HITL은 사람을 매번 모델 응답 끝에 넣는다는 뜻이 아니다. 특정 Tool 실행이나 Workflow 단계에서 정책에 의해 실행을 일시 중지하고, 승인/추가 입력을 받은 뒤 재개하는 방식이다. [D16]

15.1 왜 필요한가?#

  • 생산 관리 시스템에 대한 변경 요청
  • 외부 전송·파일 삭제·고비용 대량 조회
  • 정확성 검증이 필요한 보고서 배포
  • 데이터 분류·접근 권한 변경

15.3 승인 상태와 보안 경계#

공개 소스 개발 가이드는 Python의 로컬 승인 응답이 권위 있는 AgentSession에 기록된 대기 요청과 연결되어야 한다고 명시한다. 단지 사용자가 입력 문자열에 "approved"라고 썼다는 이유로 실행을 승인해서는 안 된다. [S09]

  • 요청 고유 ID와 Tool 호출 발생 지점을 연결한다.
  • 승인자는 누가, 어떤 데이터를, 어떤 파라미터로 바꿀지 확인한다.
  • 승인이 거부되면 사용자에게 대체 경로를 보여 준다.
  • 재개할 때 이미 수행된 Tool을 중복 실행하지 않는지 테스트한다.

15.4 Workflow 요청과 Tool 승인 구분#

요청 유형 예시 실행 맥락
Request Info '분석할 기간을 선택하세요' 사용자로부터 추가 정보 수집
Tool Approval '이 설비 설정 변경을 승인합니까?' 위험한 Tool 실행 전 승인
Review Gate '보고서 초안을 배포해도 됩니까?' 워크플로 단계 정책

Workflow의 RequestInfoEvent는 HITL 구현에 활용되며, 도구 승인은 도구별 승인 내용과 상호작용할 수 있다. [D16]

16. Checkpoint와 Persistence#

16.1 무엇을 저장하나?#

Workflow Checkpoint는 일반적으로 다음을 포함할 수 있다. [D10]

  • Executor들의 현재 상태
  • 다음 Superstep으로 전달될 메시지
  • 처리 중인 승인/요청 및 응답
  • 공유 상태와 실행 재개 위치

16.2 제공되는 Python 저장소 유형#

Store 지속성 용도
InMemoryCheckpointStorage 프로세스 내 간단한 테스트와 데모
FileCheckpointStorage 파일 시스템 단일 머신 재실행
CosmosCheckpointStorage 별도 Azure 패키지 분산·서비스 환경의 저장 가능성

FileCheckpointStorage는 로컬 경로를 명시해야 한다. CosmosCheckpointStorage를 사용한다고 자동으로 적절한 tenant 보안과 운영 정책이 완성되는 것은 아니다. [D10]

16.3 Checkpoint 최소 구조 예시#

원문 수록 코드 · 구분과 제약은 본문 참조python
from agent_framework import InMemoryCheckpointStorage, WorkflowBuilder

storage = InMemoryCheckpointStorage()

# start_executor, next_executor는 실제 Executor 객체로 미리 정의
builder = WorkflowBuilder(
    start_executor=start_executor,
    checkpoint_storage=storage,
)
builder.add_edge(start_executor, next_executor)
workflow = builder.build()

주의: 이 코드는 Checkpoint 설정 형식을 보여 주는 불완결 예제다. 요청/응답 승인, checkpoint_id를 통한 복구 등은 실제 저장소를 사용하여 별도 검증해야 한다.

16.4 Checkpoint와 외부 부작용 문제#

다음 상황을 생각해 보자.

원문 수록 코드 · 구분과 제약은 본문 참조text
Tool이 파일 업로드 성공
→ Workflow가 상태 저장 전에 프로세스 크래시
→ Checkpoint 복원
→ 같은 파일 업로드가 다시 실행

따라서 외부 작업은 적어도 중복 실행 방지 키, 정확한 완료 기록, 작업 전/후 상태 검사, 재실행 가능성을 고려해야 한다. 체크포인트는 '상태를 복원하는 장치'이지, 임의의 외부 시스템에 대해 정확히 한 번(exactly-once) 수행을 보장하는 만능 트랜잭션이 아니다.

16.5 Python v1.13.0 이후 Checkpoint 변경#

공식 문서상 v1.13.0부터 Workflow 입력 전 Entry Checkpoint 및 요청 응답 전달 시의 진입 체크포인트가 추가되어 재생 가능성을 개선했다. 고정 버전 v1.24.0에서는 문서의 오래된 저장 포맷을 그대로 전제하지 말고 복원 호환성과 실행 이벤트 순서를 확인해야 한다. [D10]
