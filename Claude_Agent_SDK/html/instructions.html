지침·설정·데이터의 신뢰 경계

system_prompt, CLAUDE.md와 파일 설정의 차이

원문 9–9장

먼저 연결해 보기

행동 지침은 SDK 옵션, 프로젝트 파일, Skill, Subagent 정의와 사용자 요청 등 여러 경로에서 들어옵니다. 검색 문서와 Tool 결과는 같은 수준의 지침이 아니라 참고 데이터로 처리해야 합니다.

파일 설정의 우선순위, 여러 CLAUDE.md의 누적 로딩, Tool 권한 규칙의 평가 순서는 서로 다른 문제입니다. 아래 조건을 단순한 문자열 병합이나 하나의 보편적 우선순위로 줄여 해석하지 마세요.

읽는 관점어떤 설정이 적용되는지와 실제 행동을 허용하는 정책을 분리해 확인하세요.

9. System Prompt·CLAUDE.md·설정 병합#

9.1 Instruction은 한 곳에만 있지 않다#

모델에게 ‘어떻게 행동해야 하는가’를 전달하는 규칙은 여러 계층에서 유입될 수 있다.

출처 예시 성격
SDK 옵션 system_prompt 실행 시 주입하는 시스템 지침
프로젝트 컨텍스트 CLAUDE.md 저장소·프로젝트의 지속적 지침
사용자 설정 ~/.claude/ 관련 설정 개인적 규칙과 설정
Skill SKILL.md 특정 작업을 수행하는 절차·리소스
Subagent AgentDefinition.prompt 위임받은 역할의 전문 지침
사용자 요청 prompt 이번 작업의 목표
Tool 결과 파일·문서·DB 응답 참고 데이터이므로 신뢰 수준이 다름

공식: [D10], [D11], [D12]

9.2 system_prompt와 CLAUDE.md의 관계#

system_prompt는 SDK 호출에서 실행 설정의 일부로 지정한다. CLAUDE.md는 프로젝트 설정 소스를 통해 읽히는 지속적인 프로젝트 지침에 가깝다. 둘은 같은 파일·같은 책임이 아니다. [D10]

원문 수록 코드 · 구분과 제약은 본문 참조python
options = ClaudeAgentOptions(
    cwd="/path/to/project",
    system_prompt="분석 결과에는 데이터 출처와 검증 불가능한 가설을 구분해 작성하라.",
    setting_sources=["project"],
)

위 코드는 사용자 정의 시스템 프롬프트와 프로젝트 설정을 함께 사용하는 개념 예시다. 실제로 어떤 기본 Claude Code 지침이 유지·교체되는지는 system_prompt의 형태(str, preset 등)와 문서의 규칙에 따르므로 단순 병합이라고 가정하지 않는다. [D10], [D03]

9.3 설정 우선순위#

공식 Python SDK 레퍼런스는 파일 기반 설정의 우선순위를 local > project > user로 설명하며, SDK 프로그래밍 옵션은 일반적인 파일 설정을 덮어쓸 수 있다. 관리형 정책은 SDK 프로그래밍 옵션보다 우선한다. 단, 특정 권한 결정에는 별도의 deny/ask/allow 순서가 있으므로 설정 병합과 Tool Permission을 혼동하면 안 된다. [D03], [D06]

주의: 파일 설정의 우선순위와 여러 CLAUDE.md가 동시에 입력될 때의 지침 해석은 다르다. 공식 문서에서는 user/project/local CLAUDE.md 내용을 누적해 읽으며, 내용 충돌 시 엄격한 보편 우선순위가 자동 적용된다고 보장하지 않는다. 상충되는 지침은 피하거나 우선순위를 명시한다. [D12]

9.4 Prompt Injection과 Instruction의 구별#

공정 SOP 문서에 ignore previous instructions 같은 문장이 포함되었다고 해서 이 문서를 시스템 지침으로 승격시키면 안 된다. 문서/검색/Tool 결과는 데이터로 취급하고, 실행 가능한 행동은 별도 권한 정책으로 제어해야 한다. [설계]
