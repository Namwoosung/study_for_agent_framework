이 문서가 1차 자료와 다른 점#

1차 자료가 “Agent, Tool, Session, Workflow가 무엇이며 어떤 기능을 제공하는가?”에 답했다면, 2차 자료는 다음을 추적한다.

  1. 호출은 정확히 어느 클래스/메서드로 진입하는가?
  2. 각 계층은 입력·출력·상태·부작용 중 무엇을 소유하는가?
  3. 모델의 Tool 요청을 누가 검증하고, 어떤 함수 호출 경로로 실제 실행시키는가?
  4. 어떤 조건에서 도구 반복, 전체 Agent 재실행, Workflow Superstep이 종료되는가?
  5. 오류·취소·승인·복구 중 정보가 무엇에 남고 사라지는가?
  6. Guardrail은 단순 지침인가, 우회하기 어려운 런타임 강제 지점인가?
  7. 같은 기능을 다른 프레임워크가 구현하는 방식과 어떤 기술적 대가(trade-off)가 다른가?

핵심 관찰: MAF는 “하나의 거대한 Agent Loop”라기보다 외부 Agent 파이프라인 + 내부 ChatClient 함수 호출 반복 + 독립 Workflow 엔진 + 선택적 Harness 재실행 루프의 결합이다. 이 네 가지를 혼동하면 Memory·HITL·병렬성·Checkpoint를 잘못 설명하게 된다. [D01][S01][S02][S08][S09]
