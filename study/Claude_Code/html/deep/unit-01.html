이 문서는 1차 Claude Code 학습 자료와 무엇이 다른가?#

1차 문서가 제품의 정체성, 구성요소, 설정 방법을 설명했다면, 2차 문서의 질문은 “실제로 어떤 계층이 언제 개입하고, 상태는 어디서 바뀌며, 실패했을 때 무엇이 남는가?”이다. 구성요소 목록을 반복하지 않고, 실행 경계·컨텍스트 변환·정책 평가·동시성·보존 상태·통제 가능한 인터페이스를 추적한다.

가장 중요한 제약: anthropics/claude-code 공개 저장소에는 배포용 안내, 릴리스 정보, 플러그인·확장 예제 등이 있지만, 핵심 Claude Code 실행 엔진의 전체 소스가 검토 가능한 형태로 공개되어 있지는 않다. 따라서 Runner._run_impl() 같은 내부 함수를 Claude Code의 실제 소스인 것처럼 창작해서는 안 된다. 이 문서의 “논리적 호출 그래프”는 실행 계약을 설명하는 모델이며, 실제 SDK의 공개 Python 코드는 CLI 호출·통신 계층에서만 직접 추적한다. 이는 Hermes·OpenAI Agents SDK·PydanticAI 등과 비교할 때 중요한 설계·검증 가능성의 차이다. 증거 등급#

표시 의미 이 문서에서 쓰는 방법
[DOC] 공식 문서에 명시된 동작 API·설정·권한의 공개 계약으로 취급
[SRC] 실제 공개 소스·릴리스·파일에서 검증 가능한 사실 링크와 경로, 확인 가능한 함수명을 병기
[OBS] 릴리스 노트에 나타난 동작·버그·수정 해당 버전의 변경 근거이며 전체 내부 알고리즘의 증거는 아님
[INF] 구현 구조 및 문서로부터 도출한 설계 해석 추정임을 분명히 표시하고 대안도 제시
[UNV] 비공개 엔진·비문서화 경계로 확인 불가능 정확한 내부 함수·순서·보장을 주장하지 않음
[PSEUDO] 학습을 위한 의사코드·가상 구성 실제 Claude Code 코드가 아님
