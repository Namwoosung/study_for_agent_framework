Hermes Agent/Memory와 Session History

핵심 원리 / 단원 04

기억과 대화 이력 나누기

짧은 사실의 주입과 과거 대화의 검색은 다른 경로다

원문 9장

먼저 연결해 보기

“측정 시각은 UTC로 표시한다”는 반복 규칙과 “지난주 분석에서 어떤 발언을 했는가?”라는 질문은 같은 저장 방식으로 다루기 어렵습니다. 전자는 짧은 사실을 남기는 Memory, 후자는 원본 대화를 찾는 Session History에 가깝습니다.

Hermes의 내장 Memory는 세션 시작 시 Prompt Snapshot으로 읽힙니다. 과거 대화 검색은 기본적으로 SQLite FTS5를 사용합니다. 외부 Memory Provider를 추가했을 때의 의미 검색 기능을 내장 검색의 기본 동작으로 혼동하지 않는 것이 이 단원의 핵심입니다. 현재 입력인 Context와도 연결해서 읽어 보세요.

읽는 관점저장 위치, 읽는 시점, 검색 방법을 각각 구분하세요. “기억했다”는 문장보다 실제 도구 결과가 중요합니다.

9. Memory: 실제로 무엇을, 어디에, 어떻게 기억하나?#

9.1 가장 중요한 구분: 세 가지 기억 경로#

계층 물리적 저장소 접근 방식 용도
Built-in Memory memories/MEMORY.md, USER.md 세션 시작 시 시스템 프롬프트에 스냅샷 주입 항상 필요한 소수의 사실
Session History state.db SQLite + FTS5 session_search로 키워드 기반 검색 및 탐색 예전 대화의 상세 사건·발언
External Memory Provider 공급자별 저장소/API Plugin이 제공하는 검색·인사이트·컨텍스트 Semantic Search, 사용자 모델링 등 확장 기능

자주 나오는 질문: 'Hermes의 장기 메모리는 RAG야?' → 일부만 검색 기반이다. 내장 MEMORY.md는 짧은 내용을 그대로 Prompt에 넣고, session_search는 기본적으로 SQLite FTS5 문자열 기반 검색이다. 기본 대화 검색을 '벡터 임베딩 RAG'라고 부르기 어렵다. 외부 Provider를 이용할 경우 별도의 의미 검색·요약·지식그래프 기능이 추가될 수 있다. S05, S07, S16

9.2 Built-in Memory의 특성#

공식 기본값(설정 가능):

  • MEMORY.md: 최대 2,200자, 환경 사실·프로젝트 관례·학습 내용
  • USER.md: 최대 1,375자, 사용자 선호·소통 방식 등
  • 저장 위치: 프로필별 <HERMES_HOME>/memories/
  • 세션 시작 시 읽어 고정된(frozen) Prompt Snapshot으로 사용

memory 도구의 주요 작업은 add, patch, remove다. 추가해 제한을 넘으면 무조건 기존 정보를 자동 삭제하는 대신 오류를 반환하고, Agent가 필요한 항목을 축약/정리해 재요청하도록 한다. 영구 메모리 파일 변경이 현재 이미 시작된 대화의 시스템 프롬프트에 실시간으로 반영되는 것은 아니다. S05

구조를 설명하는 JSON 예시json
{
  "target": "memory",
  "operations": [
    {"action": "add", "content": "분석 데이터에는 wafer_id, lot_id, step_id 컬럼이 있다."}
  ]
}

위 JSON은 공식 memory Tool 스키마 형태를 따르는 설명용 예시다. 민감한 반도체 수율·고객·공정 파라미터는 기본 Memory에 기록하지 않도록 정책을 고려해야 한다.

9.3 '기억했다'는 응답만으로 저장을 믿으면 안 된다#

공식 가이드는 모델이 실제 memory Tool을 호출하지 않았으면서 말로만 저장했다고 응답할 수 있다고 경고한다. 확인할 것은 실제 Tool Call 결과와 파일/DB 기록이다. 또한 메모리 저장 승인 옵션이 활성화되어 있으면 요청이 승인 대기 중일 수 있다. S05

9.4 세션 기반 Recall (session_search)#

구조·흐름 설명text
질문: '지난주 불량 패턴 분석에서 어떤 기준을 사용했지?'
   ↓
Agent가 관련 키워드로 session_search 호출
   ↓
SQLite FTS5로 과거 대화 메시지 검색
   ↓
발견된 대화의 전후 맥락을 더 탐색할 수 있음
   ↓
검색 결과를 현재 작업의 Context로 사용

FTS5는 full-text search 기술이다. 임베딩 검색과 달리 문장 의미가 같아도 단어가 많이 다르면 누락 가능성이 있다. 반대로 정확한 장비 식별자·에러코드·공정명처럼 문자열이 중요한 검색에서는 유용할 수 있다. 문서상 기본 session_search는 원본 메시지를 반환하며, 이 도구 자체가 검색 시마다 LLM 요약을 수행한다고 설명하지 않는다. S05

9.5 외부 메모리: Honcho 등#

공식 문서는 외부 Memory Provider Plugin을 통해 Semantic Retrieval, 사실 추출, 지식 구조화·프로필 모델링 등을 추가할 수 있다고 설명한다. Honcho는 별도 업체(Plastic Labs)의 Plugin으로, 대화 이후 사용자의 패턴과 선호를 추론하는 방식이다. Hermes에 항상 탑재·활성화된 기본 기능이 아니다. S05, S16

내부 데이터망에서 외부 메모리 서비스를 쓰려면 데이터 반출 경로, 저장 국가·리전, 삭제 정책, 인증·보관 기간 등을 검증해야 한다.

9.6 Memory에 무엇을 넣고, 무엇을 넣지 말까?#

넣기 적합 [해석] 넣지 않기 적합 [해석]
사용자에게 선호되는 출력 형식 대량의 raw 센서 시계열
도구 실행 시 주의할 일반 규칙 기밀 고객명·수율·사업 데이터
검증된 데이터 스키마의 개요 세션별 임시 분석 결과 전체
반복되는 팀 공통 비민감 규칙 비밀번호, 토큰, API 키

생산 데이터는 Memory가 아니라 별도의 접근통제된 원천 데이터 저장소에서 읽기 전용으로 조회하게 하는 편이 안전하다.
