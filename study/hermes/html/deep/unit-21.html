마지막 정리: Hermes에서 학습해야 하는 핵심 10문장#

  1. Hermes는 LLM 자체가 아니라 Agent Loop, Tool, State, Memory, Gateway를 결합한 실행 시스템이다.
  2. Agent Loop는 여러 모델 호출의 상태 전이와 예외·종료·권한·예산을 관리한다.
  3. 같은 Prompt를 다시 보내도 Provider Prefix Cache가 계산을 재사용할 수 있다.
  4. MEMORY.md의 변경과 현재 세션 System Snapshot의 변경은 별도다.
  5. SQLite FTS5는 효율적인 텍스트 검색이고, Dense Vector Retrieval의 대체 개념은 아니다.
  6. Skill 자동 생성은 문서 작성 Tool 실행이며, 검증된 지식/정책으로 자동 승격된다는 뜻이 아니다.
  7. Tool·MCP·Plugin·Skill은 각각 동작, 통신 프로토콜, 런타임 확장, 절차 지침이라는 다른 계층이다.
  8. Guardrail의 핵심은 모델 지시보다 실제 실행 경계의 정책과 권한이다.
  9. 병렬 Tool과 Subagent는 동시성 단위·Context·비용·충돌 관리가 다른 구조다.
  10. Gateway와 Cron은 Agent를 장기간 운영하고 반복 실행하는 제품 수준의 수명주기를 담당한다.

학습의 최종 질문은 'Hermes가 좋은가?'가 아니라 '왜 이런 구조이며, 어떤 문제에서 다른 구조보다 유리하거나 불리한가?'이다.
