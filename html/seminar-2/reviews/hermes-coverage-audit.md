# Hermes 학습자료 ↔ 현재 발표자료 포함 범위 검토

검토일: 2026-11-03. 발표자료와 blueprint는 수정하지 않았다.

## 1. 비교 기준과 읽는 방법

다음 세 원문을 전체 대조했다. 기본·심층 교재 HTML은 이 원문을 재구성한 자료이므로 같은 내용을 중복 집계하지 않았다.

- **기초**: [Hermes_Agent.md](../../../hermes/Hermes_Agent.md)
- **심층**: [Hermes_Agent_2차_심층_학습_분석.md](../../../hermes/Hermes_Agent_2차_심층_학습_분석.md)
- **코멘트**: [Hermes_Agent_발표_실무_시사점_코멘트.md](../../../hermes/Hermes_Agent_발표_실무_시사점_코멘트.md)

발표의 실제 청중 화면은 [index.html](../index.html), 작성 내용은 [build.py](../build.py)와 [artwork.py](../artwork.py), 슬라이드별 노트는 [notes.json](../notes.json)과 [presenter-notes.md](../presenter-notes.md)를 확인했다. [최종 blueprint](../../../2_2차_세미나_최종_slide_blueprint.md)의 비공개 C~F 해설·Q&A·Demo 설계·정정도 함께 확인했다.

Hermes 본편은 **S04~S15, 12장**이다. S03·S17·S19 및 공통 운영/검증 S43~S45에 흩어진 설명도 고려했다. 슬라이드 번호는 표시 ID 기준이다. PydanticAI의 비슷한 설명만으로 Hermes 실제 구현이 설명됐다고 판정하지 않았다.

아래 표는 단어의 부재가 아니라 **독립적으로 설명할 가치가 있는 내용 단위의 미포함·축약**을 정리한 것이다. 같은 내용이 원문의 여러 절에 반복되면 하나로 묶었다. 따라서 56개 항목은 56개 새 슬라이드를 뜻하지 않는다.

현재 상태:

- **미포함**: 해당 설명을 Hermes 장표·노트에서 찾기 어려움.
- **축약**: 상위 개념·이름은 있으나 표에 적은 내부 동작·조건이 빠짐.
- **다른 위치**: 공통 장표·비공개 설계 등에 있으나 Hermes 설명으로 연결되지 않음.

권장:

- **본편 보강**: 기존 장표에 짧은 흐름·사례·문장을 추가.
- **본편 신설**: 별도 도식 장표를 추가할 가치가 큼.
- **노트/부록**: 본편에서는 생략하고 질문·심화 설명용으로 준비.
- **제외 유지**: 이번 2차 발표에는 넣지 않고 학습자료 또는 3차로 연결.

기술적 사실은 **현재 폴더의 학습자료 기준**이다. 이번 검토에서 최신 Hermes를 다시 조사하거나 실행한 것은 아니다. 원문의 `[SRC]`·`[DOC]`·`[INF]` 구분을 유지해야 하며, 설계 제안을 Hermes 내장 기능으로 바꾸어 설명하면 안 된다.

## 2. 우선 판단

현재 발표는 **전체 아키텍처 → 요청·루프 → Context·Cache·Memory·검색·Skills → 확장 → 동시성 → 정책**의 개념 흐름을 이미 갖췄다. 가장 큰 공백은 다음 세 가지다.

1. **실행 무결성**: Tool을 실행하기 전에 무엇을 기록하고, 실패·재시도·취소 때 무엇이 남는가?
2. **운영 수명주기**: Gateway가 같은 세션의 요청 순서와 쓰기를 어떻게 소유하며, 장기 실행과 제어 메시지를 어떻게 다루는가?
3. **자동화의 보장 범위**: Cron의 예약 슬롯 중복 방지와 외부 부작용·결과 전달의 성공은 어떻게 다른가?

구성 권장안은 **기존 S06·S09·S10·S12~S15 보강 + Gateway 1장 + Cron 1장**이다. Hermes가 현재 12장이므로 이 안은 14장 규모다. 시간이 고정되어 있다면 새 장표 수보다 설명량을 먼저 조정하고, Cache 세부 구현·설치·파일 지도는 노트로 보낸다. 기술적 채택 기준 요약은 시간을 확보하면 세 번째 신설 장표 후보로 둔다.

## 6. 다음 개선 단계 제안

1. **S06 실행 경로 보강**: H02/H04/H05/H29를 한 흐름으로 통합한다. 검증·저장·정책·실행·결과 기록의 각 실패가 어디서 멈추는지 설명한다. 특수 Tool 경로가 다를 수 있다는 기존 주석을 유지한다.
2. **S09~S12 상태 흐름 보강**: 압축의 prune/summary 순서, 실제 Memory 저장과 frozen snapshot의 분리, Skill 변경 승인과 SOP 경계를 각각 기존 도식에 추가한다. H15 업무 사례는 두 장에서 반복하지 않는다.
3. **S14~S15 실행 통제 보강**: barrier·요청 순서로 결과 반환·취소와 rollback 차이·off와 강제 차단의 차이를 눈에 보이게 만든다.
4. **Gateway 장표 신설**: H01/H43/H44/H45와 코멘트 §3을 묶는다. Agent 운영과 모델 서빙의 역할은 유지하고 실제 세션 쓰기 소유권을 추가한다.
5. **Cron 장표 신설**: H46/H47을 묶고 H48은 노트에 둔다. Agent 작업 모드의 예시임을 명시한다.
6. **채택 판단 마무리**: H30/H42/H51의 선택 기준을 대본에 넣는다. 시간이 남으면 Hermes 종료 전 ‘어떤 업무에 맞는가’ 한 장으로 독립시킨다.

장표 신설 시 기존 ID를 즉시 전부 재번호하지 않고 초안에서는 `S14A`, `S14B`처럼 참조용 임시 ID를 쓰는 방법이 있다. 실제 편집을 시작하면 탐색·노트·PDF·Demo 복귀 ID까지 일관되게 갱신해야 한다. 이번 검토에서는 해당 편집을 수행하지 않았다.
