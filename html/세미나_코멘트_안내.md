## 내용의 구분

- 기존 기술 설명: 원래 학습 원문의 버전과 근거를 그대로 읽습니다.
- 추가 코멘트: 해당 설명에서 도출한 설계 해석, 반도체 가상 사례, 활용 이점과 책임입니다.
- 3차 확인 질문: 실제 Agent·Tool·저장·동시성 실험에서 확인할 후속 과제이며 실측 결과가 아닙니다.

원문의 SOP 변경, 승인, 외부 부작용 같은 일반 경고를 반복하기보다, 어떤 업무 계약을 정할지와 무엇을 비교·관찰해야 하는지에 집중했습니다. 다른 발표자가 맡은 LangChain/LangGraph·모델 추론 서빙 내부 설명은 확장하지 않았습니다. GPU 수·Worker 수·성능 개선 수치도 추정하지 않았습니다.

## 파일과 원문 보존

- `html/seminar-comments.json`: 추가 코멘트의 편집 원본. 기존 문서의 정확한 절과 근거를 기록합니다.
- 각 주제 폴더의 `*_발표_실무_시사점_코멘트.md`: 해당 주제의 추가 코멘트만 모은 문서. JSON에서 생성합니다.
- 심층 교재 본문 뒤의 추가 해설: 원문 영역 바깥에 별도 블록으로 배치합니다. 기본 교재 본문에는 중복 삽입하지 않습니다.
- `html/seminar-baseline.json`: 작업 전의 모든 기존 Markdown·HTML 해시.
- `html/seminar-validation.json`: 보존 검증 결과.

이 작업 전의 원본 Markdown, 발표 흐름, 1차 blueprint, 비교 분석 문서와 기존 교재의 문구를 삭제·수정하지 않습니다. HTML에서는 추가 블록만 제거했을 때 기존 파일의 해시가 정확히 같아야 합니다.

## 갱신과 검사

프로젝트 루트에서 실행합니다.

```sh
node html/apply-seminar-comments.mjs
node html/validate-seminar-comments.mjs
node html/validate-home.mjs
```

추가 블록은 중복 없이 다시 적용할 수 있습니다. 전체 홈 빌드의 후처리로도 연결되어, 기존 교재를 재생성한 뒤 코멘트가 복원됩니다. 원문이 바뀌어 SHA-256이나 기준 절이 달라지면 자동으로 옮겨 달지 않고 근거를 재검토하도록 오류를 냅니다.

보존 검사의 기준 해시는 이번 작업 직전의 파일입니다. 이후 원문을 의도적으로 바꾸거나 교재 구성을 바꾼 경우에는 변경 내용과 코멘트의 타당성을 검토한 다음 기준을 새로 정해야 합니다.
