이 문서를 읽기 전에: 가장 중요한 결론 10가지#

  1. ADK는 LLM 자체가 아니라 Agent 애플리케이션을 구축·실행·평가하는 개발 프레임워크이다. LlmAgent는 모델 기반 의사결정, Runner는 실행 환경과 서비스 연결을 담당한다. [D01][D02][S01]
  2. ADK의 핵심 설계 단위는 Agent만이 아니라 Event와 Session이다. 모든 도구 호출·응답·상태 변경을 이벤트 흐름으로 관찰할 수 있는 구조가 중요한 차별점이다. [D04][D05][S01]
  3. Session, State, Memory, Artifact는 서로 다르다. 대화 이벤트, 구조화된 현재 상태, 별도로 검색하는 장기 기억, 파일/결과물을 혼동하지 말아야 한다. [D04][D05][D06][D07]
  4. Agent Loop는 LlmAgent만의 코드가 아니다. LlmAgent._run_async_impl()이 BaseLlmFlow.run_async()를 호출하고, 후자는 모델 호출 단계와 도구 호출 후처리를 반복한다. [S02][S03]
  5. SequentialAgent·ParallelAgent·LoopAgent는 사전 정의된 실행 패턴이다. ADK 2.0은 별도로 그래프 기반 Workflow를 지원해 조건 분기, 데이터 전달, 승인, 노드 실행을 보다 명시적으로 표현한다. [D08][D09]
  6. 모든 기능이 자동으로 제공되는 것은 아니다. 메모리 백엔드, 저장소, 사내 데이터 도구, 계정 권한, 내용 검증, 평가 데이터셋 등은 사용자가 구성해야 한다.
  7. Tool은 LLM이 실제 코드를 실행할 수 있는 제한된 통로다. Python 함수를 도구로 노출하는 것이 곧 안전한 실행을 의미하지는 않는다. 접근 권한과 서버 측 검증이 필수다. [D02][D10]
  8. MCP와 A2A는 역할이 다르다. MCP는 주로 외부 도구·데이터 연결, A2A는 별도의 Agent 시스템 사이의 통신·협업에서 중요하다. [D11][D20]
  9. ADK는 Gemini 전용이 아니다. LiteLLM 등 다른 모델 연동 경로가 있지만, 모델별 Function Calling·Structured Output·호출 규약의 실제 호환성은 검증해야 한다. [D12]
  10. 반도체 분야에서는 모델의 자율성보다 데이터 품질, 접근 통제, 검증 가능성이 우선이다. ADK는 이를 구성할 기반을 제공하지만, 측정 단위·Lot/Wafer ID·통계 검증·생산 시스템 권한은 별도 설계해야 한다.
