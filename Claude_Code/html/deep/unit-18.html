최종 요약 — 발표자가 기억할 15문장#

  1. Claude Code는 Claude 모델이 아니라 모델을 반복 사용하고 Tool·상태·권한을 관리하는 Agent Harness다.
  2. Claude Agent SDK는 이 Harness를 프로그램에서 재사용하는 인터페이스이며 별도의 공개 Agent Loop 구현이라고 봐서는 안 된다.
  3. 모델은 무엇을 할지 제안하고, Harness·Host는 실제 실행 권한과 결과를 통제한다.
  4. Prompt는 System/Project/Conversation 계층으로 구성되며, 앞부분이 안정적일수록 Prefix Cache에 유리하다.
  5. Prompt Caching은 메모리가 아니라 동일 입력의 재계산을 줄이는 메커니즘이다.
  6. Compaction은 대화 내용을 요약·대체하는 것이고, 정보 손실 가능성이 있다.
  7. CLAUDE.md·AGENTS.md는 Instruction 파일이며, 파일 선택과 로딩 시점은 설정에 의존한다.
  8. Auto Memory는 선택된 정보를 파일로 저장하고 색인을 통해 재사용한다. Session 전체를 영구 보존하는 것과 다르다.
  9. Skill은 작업 절차의 재사용이며, 올바른 지식을 자동 보장하지 않는다.
  10. MCP는 외부 Tool 연결 프로토콜, Plugin은 구성요소의 배포 단위, Hook은 이벤트 제어 장치다.
  11. Guardrail은 Instruction·Permission·Hook·Sandbox·Backend ACL을 합쳐야 실효성이 생긴다.
  12. 병렬 Tool, Background Process, Subagent, Agent Teams는 실행 단위·상태 공유·비용이 다르다.
  13. claude -p를 HTTP 뒤에 붙인다고 Production-grade Agent Server가 자동 완성되지는 않는다.
  14. 공개 SDK에서 Transport·Callback·Message Parser는 분석할 수 있지만, Claude Code 코어의 모든 함수는 공개되어 있지 않다.
  15. 이 문서를 공부하는 목적은 사용법 숙달보다, Agent Framework를 직접 설계한다면 어떤 상태·정책·동시성·복구 계약을 작성해야 할지 이해하는 것이다.
