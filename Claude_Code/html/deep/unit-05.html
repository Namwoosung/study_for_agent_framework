10. Context를 코드 수준에서 추적하는 관찰 가능한 경계#

Claude Code 코어의 assemble_final_prompt() 같은 실제 함수를 공개 소스에서 확인할 수는 없지만, 다음 공개 인터페이스로 구성 변경을 추적할 수 있다.

  • /context: 현재 Context Window와 로딩된 메모리·스킬 등의 가시적 상태 점검. DOC
  • /usage: Prompt Cache의 적중/미스 추세 확인. DOC
  • InstructionsLoaded Hook: Instruction 파일 로딩 이벤트를 관찰. 단, AGENTS.md를 전용 로더에서 읽는 경우 이벤트 특성이 다를 수 있음. DOC[R05]
  • PreCompact/PostCompact Hook: 압축 시점 및 압축 후 추가 정보 주입 기회 확인. DOC
  • claude -p JSON/Stream 출력: 공개되는 Tool/Message 이벤트 추적. 공개된 정보가 실제 요청 원문 전체를 보장하지는 않음. DOC
  • SDK의 SystemMessage·AssistantMessage·UserMessage·ResultMessage 등 메시지 타입: CLI에서 외부에 노출한 정보 확인. SRC[R26]

주의: 디버그 로그 또는 Proxy 트레이스를 통해 모델 입력 전체를 볼 수 있다 해도 기밀 Prompt·OAuth Token·Tool Output을 그대로 기록하면 보안 사고가 될 수 있다. 분석용 로그는 기본적으로 마스킹·샘플링·접근 통제한다.
