21. Hook을 정확히 분석하려면 어디를 봐야 하나?#

Hooks는 SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, Stop, SubagentStart/Stop, PreCompact/PostCompact 등 수명주기의 특정 이벤트를 가로챌 수 있다. Handler는 Command, HTTP, Prompt 또는 Agent 기반 등 지원되는 유형을 사용한다. DOC[R13]

21.1 모델이 판단하는 것 vs 강제 실행되는 것#

동작 모델이 자발적으로 선택? 실패·차단 정책
Skill을 사용하라는 Instruction 일부 판단에 의존 보장된 강제가 아님
PreToolUse Hook Tool 호출 이벤트에 연결 지정한 반환·종료코드·timeout 정책 적용
PostToolUse Hook Tool 완료 이벤트에 연결 이미 발생한 외부 효과는 소급 차단 못함
Stop Hook 종료 이벤트에 연결 마무리 검증·조건부 종료 차단 가능
PermissionRequest Hook 승인 요구 시 연결 사용자 대신 승인/거부 동작 가능, 사용 조건 제한
PreCompact Hook 압축 직전 이벤트 요약 전 필요한 맥락 처리 가능
InstructionsLoaded Hook Instruction 로더와 연결 별도 AGENTS.md 경로에서는 이벤트 차이 있음

21.2 PreToolUse의 특별한 경계#

공식 Hook Reference는 사용자가 @file로 입력에 포함한 파일 내용은 Tool 호출 없이 Prompt 구성 단계에 들어갈 수 있으므로, Read Tool용 PreToolUse가 실행되지 않을 수 있다고 경고한다. 따라서 민감 파일 유출 방어를 PreToolUse(Read)에만 맡겨서는 안 된다. Read deny 및 Host 접근 제어 등 추가 레이어가 필요하다. DOC

PreToolUse는 allow, deny, ask, defer 등의 제어 계약을 갖지만, SDK Callback Hook의 타임아웃 처리와 로컬 Command Hook의 실패 처리는 별개로 확인해야 한다. DOC

21.3 Hook 예제는 모델 수준 정책이 아니다#

원문 수록 코드 예시 · 실행 미검증json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 .claude/hooks/check_shell.py"
          }
        ]
      }
    ]
  }
}

위는 공식 문서의 Hook 설정 형식을 따른 교육용 스케치다. check_shell.py 파일은 구현되지 않았고, 이 설정만으로 어떠한 명령도 차단되지 않는다. 별도의 Handler가 표준 입력 JSON을 파싱하고 공식 Hook 응답 스키마에 맞춰 명시적으로 거부해야 한다. Hook을 켠다는 사실과 보안 강제가 된다는 사실은 다르다.

21.4 Hook 완료와 Tool 완료를 혼동하지 말 것#

  • PreToolUse 종료 시점: Tool 실행을 허용/차단/수정할 수 있는 경계.
  • PostToolUse 종료 시점: Tool 실행 뒤 결과를 보고 검증할 수 있는 경계.
  • Stop: 대화가 끝나려는 경계. 파일수정·외부 배포의 실제 완료 또는 롤백을 보장하지 않음.
  • SessionEnd: 세션 종료 알림이지 백엔드 트랜잭션 commit이 아님.

코드 설계 관점: 이벤트 Hook의 이름·input schema·output schema·timeout·실패 기본값을 표로 정리하는 일이 Agent Framework를 처음 만드는 사람에게 핵심적인 작업이다.
