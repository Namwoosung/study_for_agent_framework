44.1 Hermes와 비교 시 중요 질문#

Hermes는 사용자 지향 완성형 Agent Runtime/CLI/Gateway를 갖추므로 메모리·Skills·Cron·Gateway 등 기능이 하나의 시스템으로 묶여 있다. OpenAI Agents SDK는 개발자에게 자신의 서비스 안에 Agent Engine을 포함할 자유를 주는 쪽에 가깝다. 기능 수만 비교하지 않고 목적과 책임 경계를 함께 비교해야 한다.

44.2 PydanticAI와 비교 시 중요 질문#

PydanticAI의 Node/Graph 구조는 상태 전이가 클래스 구조에 더 명시적으로 드러날 수 있고, OpenAI SDK는 RunResult와 NextStep 중심으로 실행 결과를 분류한다. 두 프레임워크 모두 Pydantic/타입 검증을 활용하지만, 타입 정의가 실행 흐름의 중심인 정도와 Output Retry·Dependency 처리 방식은 별도 비교해야 한다.

44.3 Google ADK와 비교 시 중요 질문#

ADK는 Runner/Event/Session/State의 이벤트 흐름을 중심으로 설명할 수 있다. OpenAI SDK는 RunItem과 Session 보존, NextStep를 중심으로 분석한다. 두 시스템의 Event 처리와 복원 가능성, Agent 교체 및 Model Input History 변환 방식의 차이를 확인해야 한다.

44.4 Microsoft Agent Framework와 비교 시 중요 질문#

MS Agent Framework는 일반 Agent Pipeline 외에 Workflow Executor·Edge·Superstep과 Checkpoint를 제공한다. OpenAI SDK의 Handoff를 MS Workflow의 Edge 또는 Checkpoint와 1:1 매칭해서는 안 된다. LLM 기반 동적 위임과 명시적 Workflow 제어를 구분해야 한다.

44.5 Claude Code / Claude Agent SDK와 비교 시 중요 질문#

Claude Agent SDK는 공개 Python SDK와 번들 CLI Runtime의 경계가 존재한다. OpenAI SDK는 Runner 주요 구현이 Python 공개 코드에 있어 직접 추적 가능하다는 장점이 있다. 반대로 CLI Harness가 제공하는 파일·프로세스·프로젝트 기반 기능은 일반 SDK만으로 자동 대체되지 않는다.
